## Summary

When a cardholder disputes a payment, the card scheme sends the Bank a dispute (chargeback) notice. Disputes Operations keeps these in a spreadsheet today, so reconciliation cannot see which settled payments are disputed, and the scheme's response deadlines are tracked by hand. The settlement service should record each dispute against the captured payment it names.

## What to build

A new module, `services/settlement/dispute_intake.py`, with one function:

`record_dispute(conn, transaction_id, card_number, amount, reason_code, received_on, actor)`

1. Look up the card transaction by its id.
2. Refuse the dispute, with a clear reason, when:
   - the transaction is unknown;
   - the transaction is not CAPTURED;
   - the amount is not positive, or is more than the transaction's amount.
3. Store the dispute in a `disputes` table, created if it is missing (CLR-WIKI-024 C6). Store:
   - the card number masked to its last four digits;
   - the amount;
   - the reason code as the scheme sends it;
   - the date it was received;
   - the status OPEN.
4. Emit an audit event for it (PAY-030).
5. Return the stored dispute.

Unit tests go in `services/settlement/test_dispute_intake.py`: one for an accepted dispute and one for each refusal (TST-001).

## Acceptance criteria

- The module's tests pass (TST-001).
- Money is a decimal from input to storage, never a float (PAY-012).
- A full card number never reaches a log, a table, an audit event or a return value: only its last four digits do (SCS-021, SCS-022).
- Every query uses bound parameters (SCS-031).
- The module is documented to STD-DOC: the header, a docstring for every function, the requirement on money logic, and the AI disclosure if an assistant helped (DOC-001, DOC-002, DOC-006, DOC-007).
- The change passes the pre-merge checks (REV-002) and is verified against STD-SVS, which adopts OWASP ASVS 5.0.0 Level 2. The results are kept with the change record (SVS-020).
- The change is committed to the Bank's repository on `feature/DSP-2026-03`, labelled AI-assisted where an assistant helped (TEC-POL-005 clause 4.4), for review under REV-005.

## Out of scope

- Receiving the scheme's notices (they arrive as files; a later story).
- The later stages of a dispute: representment, and posting the chargeback.
