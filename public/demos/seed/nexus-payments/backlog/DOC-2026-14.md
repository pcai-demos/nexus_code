## Summary

Internal Audit tested the clearing batch, `CLEARING.cbl`, against the Code Documentation Standard, as part of its review of systems whose behaviour few people know (TEC-POL-004 clause 4.6). Its comments cannot be relied on:

- **F1.** The header names Nexus Payments Ltd as the copyright owner. It gives no purpose, service, owner, classification, change history or requirements (DOC-001).
- **F2.** No division, section or paragraph has a purpose comment (DOC-002).
- **F3.** A comment says fees are truncated to the penny; the code rounds them (DOC-003).
- **F4.** A comment holds a card number (DOC-004).
- **F5.** An old COMPUTE is left in as a comment (DOC-005).
- **F6.** The fee calculation does not name the requirement it implements (DOC-006).

## Why now

- The batch's last COBOL maintainer retires at the end of September. After that, its comments are what the next engineer has.
- MOD-2026-07 ports the batch to Java and leaves these comments out of scope. The COBOL stays the reference through the parallel run, and the fallback after cut-over (MIG-006).

## What to do

1. Bring the comments in `legacy/clearing-batch/CLEARING.cbl` up to STD-DOC in one comments-only change, with the team's header (CLR-WIKI-021).
2. Change no line of code (DOC-008).

## Acceptance criteria

- A tool shows that no line of code changed, and the COBOL check still passes: the same report from the same input (DOC-008, CLR-WIKI-019).
- The header carries every field DOC-001 lists, with the Bank's notice (LEG-POL-001 clause 4.2).
- Every division, section and paragraph has a purpose comment (DOC-002).
- No card number and no commented-out code remain (DOC-004, DOC-005).
- If an AI assistant drafts the comments, the header says so (DOC-007) and the pull request is labelled AI-assisted (REV-005).

## Out of scope

- Any change to what the program does. A defect found in the code is its own ticket (MIG-002).
- The Java and Rust ports (MOD-2026-07).
